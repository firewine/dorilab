# 근거 기반 사례·설명 생성용 지시문 초안

입력: 검토할 능력, 가용 fact와 원문 구간, action contract, 승인된 업무 범위, source/program split.

한 사례에서 엔지니어가 결정할 질문을 한 문장으로 작성한다. 검토 대상 제안, 현재 관측, 제공하지 않은 정보, 적용범위를 분리한다. 원문에 실제 존재한 시험과 가상 counterfactual을 구분한다. 가상 수치·승인·관측에는 가상 표시를 붙인다.

A/B 대조쌍은 실제로 결론을 바꾸는 한 조건 또는 명시한 최소 조건 묶음만 변경한다. A/B 이름이나 문서의 어휘 패턴만으로 label을 알 수 없도록 한다. changed_paths와 그 변화의 공학적 효과는 작성자 메타데이터로 보관하며 모델 입력에서 제외한다.

출력은 schemas/review_explanation_v1.json의 짧은 외부 설명과 별도의 action target을 포함한다. basis는 관측 사실, 문헌 원리, 그 둘의 연결을 구분하고 evidence_refs를 붙인다. 2~4문장의 근거 중심 설명을 작성하며 장문의 생각 독백을 요구하지 않는다.

여러 다음 행동이 동등하게 타당하면 acceptable_answers 또는 최종 완료조건으로 나타내고 정답 하나를 억지로 정하지 않는다. 근거 부족과 제안 반박을 구분한다. NO_ACTION_REQUIRED는 한 검토항목에 대한 상태이며 제품 전체 합격이 아니다.

정답 후보와 rationale은 reference_draft에만 둔다. 학생 모델 입력에는 질문·관측·원문 근거·가용 도구만 보낸다. 생성 결과 상태는 CANDIDATE이며 자동 GOLD 승인을 하지 않는다.
