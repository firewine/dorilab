# DoriLab 개발 결과 명세 묶음

문서 버전 **1.0** | 기준일 **2026-09-27 UTC** | 상태 **현재 구현 기준(as-built), 아키텍처 §11은 개발 예정**.

대상은 프로젝트별 장기기억, Qwen 검색 제어기, RC3 검토 연결, 단일 GPU 추론 서비스다. 현재 코드와 기존 검증 증적으로 확인한 동작을 기록한다.

[아키텍처 §11](ARCHITECTURE_KO.md#11-논문-데이터-플라이휠--개발-예정)은 논문 수집부터 검색, 피드백, 학습 데이터 생성, 후보 모델 평가와 배포까지의 개발 예정 구성을 기술한다. 해당 절의 구현 상태는 **개발 예정**이다.

| 문서 | 주요 내용 | 권장 독자 |
|---|---|---|
| [아키텍처](ARCHITECTURE_KO.md) | 현재 구성과 처리 흐름, 모델 공유, 저장, 캐시, 권한 경계, 개발 예정 논문 데이터 플라이휠 | 제품 담당자, 시스템 설계자, 운영자 |
| [입출력 명세서](IO_SPEC_KO.md) | trajectory, 검색, 계획, 검토 데이터, CLI, HTTP, 오류, hash와 증적 형식 | API, 클라이언트, 데이터 연동 개발자 |
| [개발 명세서](DEVELOPMENT_SPEC_KO.md) | 모듈 책임, 함수 인터페이스, 알고리즘, 상태 전이, 검증 기준, 실행 환경 | 구현, 유지보수 개발자 |
| [소스 기준선](SOURCE_BASELINE.json) | 문서 작성 시점의 관련 파일 SHA256 | 변경 추적 담당자 |
| [문서 점검 결과](DOC_VALIDATION.json) | 링크, JSON 예제, 소스 불변성 점검 결과 | 검토자 |

현재 기준선은 코드의 버전과 별도로 관리한다. 이후 코드가 바뀌면 명세와 SOURCE_BASELINE.json을 함께 갱신해야 한다. 이번 작업의 변경 범위는 명세 문서와 문서 점검 기록이다.

검증 수치의 근거는 [제어기 검증 receipt](../../project_memory/artifacts/controller_v1/verification.json)다. CPU/서비스 검사37개 및 합성 입력 HTTP 검증은 기존 수행 결과를 인용한다. 이번 문서 점검은 링크, 예제, 소스 기준선과 문체를 대상으로 한다.

문서에서 다음 표현을 구분한다.

- **코드 검증**: 실제 Python/HTTP 계층에서 조건을 확인하고 거부한다.
- **모델 계약**: 고정 system prompt가 요구하는 출력 규격이다. 출력 유효성은 별도 검증한다.
- **운영 전제**: 신뢰된 로컬 운영자, 단일 호스트 writer 등 배포자가 지켜야 한다.
- **지원 범위**: 현재 제공하는 기능과 추가 구성이 필요한 운영 조건을 정의한다.
